Status: approved 2026-11-27.

Scope is docs/design.md "v2 scope" and ADR 0010. Each step below is one `feature/*` PR to `main` with CHANGELOG, README and docs updated in the same PR. Per the delegation rules each code PR goes planner → builder (in a worktree) → verifier → PR → review gate → CI. Gating logic is test-first.

- zod schema and loader in `lib/curated.ts`: optional `area` on items and optional missions; rules from docs/design.md "Data model (sketch)" (known area, area visible no later than the entry or the optional's anchor, district no earlier than its parent). `parseCurated` fails on any issue.
- `lib/gates.ts`: `isAreaVisible(area, currentMission)` and `areaName` (the title-lookup pattern: names only through one deliberate call).
- `lib/curated.data.test.ts`: no item or optional text names an area before the area is visible.
- No migration: areas are curated, and nothing new is stored.
- Done when: the rules have failing-then-passing tests on the fixture, the real data parses, and the text rule passes on all four gates' items. Done 2026-11-27: six regions in `areas.yaml`, all visible from `prologue`; `aliases` per area; the text rule covers every renderable curated string (ADR 0010 update).

## 4. Map view models (test-first)

- `lib/map.ts`: `mapView(data, current, checks)` (regions with reached flag, name only when reached, badge count of the unticked rows its area sheet shows, rolled up from districts; the Anywhere rows) and `areaSheet(data, current, checks, slug)` (null for a hidden, unknown or not-yet-visible area). Both build on the rows of `checklistView`'s sections so counts and chips match the checklist.
- Leak tests: every mission as the current one on the real data; fail on a later area name or slug, a later main mission title, an unopened optional, a hidden item or any locked count.
- Done when: fixture tests cover reached and unreached regions, badges, rollup, unticked closed rows left out, Anywhere and the 404 cases; leak tests pass. Done 2026-11-27: `lib/map.ts` with `mapView` and `areaSheet`; an unreached region is only its file-order `index` among the top-level areas (step 5's schematic draws one shape per region in that order); rows gain a visible-only `area: { slug, name }` (`areaTag` in `lib/gates.ts`) on the checklist and Home's Up next, so step 5 only renders the tag; leak tests run every mission as the current one on the real data and on a fixture with later areas.

## Risks to watch

- **Area names as spoilers:** an area reached late named early, in the map, a row tag, a detail page, item text or a URL. Mitigated by per-area visibility, the text rule and leak tests over every mission.
- **Location leaks by count:** a per-area count of locked content tells the player where future content is. The map shows no locked counts (ADR 0010).
- **Region boundaries and reach order are thin at launch:** best evidence with the safe tie-break (latest plausible visibility), re-researched weekly (ADR 0008).
- **Schematic IP:** the drawing must be original. No tracing from screenshots, key art or fan maps.
- **A large Anywhere list early on** makes the map look empty. Step 3 places the next gate's entries before the Map ships.
- **Five tabs at 375px:** 75px per tab; check labels fit at the default font size and with larger text settings.
